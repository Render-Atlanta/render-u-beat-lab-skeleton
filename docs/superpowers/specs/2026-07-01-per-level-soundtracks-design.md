# Per-level soundtracks for RenderATL Rush (#126)

**Date:** 2026-07-01
**Issue:** [#126 — Generate per-level soundtrack for RenderATL Rush](https://github.com/render-u-beat-lab/issues/126)
**Repos:** Beat Lab (`render-u-beat-lab`, primary) + RenderATL Rush (`../renderatl-rush`)

## Problem

RenderATL Rush plays a single hardcoded, procedurally-synthesized loop for every
stage (`AudioBus.js` `SYNTH.music`, ~line 217). We want a distinct,
genre-appropriate track per level, **generated by Beat Lab** so each track stays
editable (re-openable as a Beat Lab project), rather than baked-in synthesis.

Beat Lab already ships every genre as a built-in style and has a Node-safe offline
WAV renderer (`renderArrangementWav`) that — after the #124 fix — sounds like the
editor.

## Scope decisions

### Stage coverage — 6 tracks, 3D reuses Connector
The real targets in `renderatl-rush/src/sim/constants.js` are the **6** entries of
`STAGES` (Airport Arrival, Connector Sprint, Badge Pickup, Vendor Hall, Main Stage,
Afterparty Sprint) plus the standalone `DRIVING3D_STAGE`. This matches the issue's
original mapping table.

- Generate **6 tracks**, one per stage.
- `DRIVING3D_STAGE` (a 3D "Connector Sprint" variant, `scene: "connector3d"`)
  **reuses the Connector track** — same theme, one fewer committed binary. Can
  split later if desired.

Each stage already carries a stable `scene` identifier
(`airport`, `connector`, `badge`, `vendor`, `mainStage`, `afterparty`). That value
is the **track slug** — used for the WAV filename (`<slug>.wav`), the `.beatlab.json`
basename, and the Phaser audio-cache key. The 3D stage shares the `connector` slug.

### Genre → stage mapping
| Stage (`scene` slug) | Genre (`BeatStyleId`) | Base BPM |
| --- | --- | --- |
| Airport Arrival (`airport`) | `afrobeats` | ~108 |
| Connector Sprint (`connector`, + 3D) | `trap` | ~140 |
| Badge Pickup (`badge`) | `rnb` | ~92 |
| Vendor Hall (`vendor`) | `bounce` | ~98 |
| Main Stage (`mainStage`) | `crunk` | ~80 |
| Afterparty Sprint (`afterparty`) | `amapiano` | ~112 |

BPM and pattern/melody tweaks live per-stage in the script's spec table and are
freely tunable.

### Artifact flow — split by purpose (two PRs)
The two repos are separate git repos. To avoid committing the same binary twice,
artifacts are split by their purpose (matching the issue's own framing):

- **`.beatlab.json` → committed in Beat Lab** at `game-tracks/<stage>.beatlab.json`
  — the editable, re-openable source of truth (a `BeatLabProject`).
- **`.wav` → committed in RenderATL Rush** only, at `assets/audio/<slug>.wav` — the
  playable asset (imported via Vite `?url`, matching the repo's existing
  `assets/scenery/*.png?url` convention; there is no `public/` dir).

Therefore **two PRs**: (1) Beat Lab adds the render script + committed
`.beatlab.json` specs; (2) RenderATL Rush adds the WAVs + loader wiring. Land Beat
Lab first (it produces the artifacts), then Rush.

## Architecture

### Beat Lab: `scripts/render-game-tracks.ts`
A `tsx` script mirroring `scripts/generate-style-profiles.ts` (top-level `main()`,
relative imports of `../src/lib/*`).

**Per-stage spec table** — one entry per stage:
```ts
interface GameTrackSpec {
  slug: string;           // "airport" | "connector" | ... → file basenames + audio key
  styleId: BeatStyleId;   // afrobeats | trap | rnb | bounce | crunk | amapiano
  bpm: number;
  bars: number;           // loop length in bars (default 4)
}
```

**For each spec:**
1. `loadKitFromDisk()` → `DecodedKit` (Node-safe; 22050 Hz).
2. Build a `SequencerState` via `createDefaultSequencerState(styleId)` and set
   `bpm`.
3. Build the loop `Arrangement`. **The export validator requires all four section
   ids** (`intro`/`main`/`variation`/`outro`) — a single-section arrangement would
   make `exportProjectJson` throw. So use `createDefaultArrangement()` (all four
   sections) and extend the `main` section to `bars` via
   `setSectionBars(arrangement, "main", bars)`. The default per-section mutes make
   the loop breathe (intro/outro are "thin", so the wrap seam is smooth) and bars
   butt at exact boundaries with the decay tail dropped when tiling, so the file
   loops without a click. The **same** arrangement feeds both the render and the
   `.beatlab.json`, so the committed project faithfully reproduces the WAV.
4. `createPlayableStyle(sequencer)` → `BeatStyle`.
5. `renderArrangementWav({ sequencer, style, kit, arrangement })` → `Uint8Array`
   (WAV bytes, 22050 Hz mono).
6. Write `<beatlab>/game-tracks/<slug>.beatlab.json` via
   `createBeatLabProject({ sequencer, arrangement })` → `exportProjectJson(project)`.
7. Write `<rush-audio-dir>/<slug>.wav` — the Rush audio dir defaults to the sibling
   checkout (`../renderatl-rush/assets/audio`) and is overridable via CLI arg / env
   var so
   the script degrades gracefully (writes the JSON, warns, skips the WAV) when the
   sibling isn't present.

Add an npm script: `"generate:game-tracks": "tsx scripts/render-game-tracks.ts"`.

**Loop length / size:** with `main` = 4 bars the total loop is ~7 bars ≈ 12–20 s ≈
a few hundred KB per WAV (mono, 16-bit, 22050 Hz). Tunable per stage via `bars`.

### RenderATL Rush: wiring
1. **Commit WAVs** at `assets/audio/<slug>.wav` (6 files). This is the game's first
   committed audio; the "zero binary audio" convention is deliberately relaxed here
   (user-approved, small looped WAVs only).
2. **Add a `music` field** to each of the 6 `STAGES[i]` — the value is the track
   slug / audio-cache key (`"airport"`, `"connector"`, …). (`DRIVING3D_STAGE` /
   `Driving3DScene` are unmerged pseudo-3D WIP on `codex/95-pseudo3d-racer`, absent
   from `main`; wiring `music: "connector"` there is a follow-up for when that
   branch merges.)
   Connector 2D and `DRIVING3D_STAGE` both use `"connector"`.
3. **Asset manifest + preload:** in `src/assets.js`, `import <slug>Music from
   "../assets/audio/<slug>.wav?url"` and expose an audio manifest
   (`AUDIO: [{ key, url }]`, de-duplicated by key). In `BootScene.preload`, after
   `preloadAssets(this)`, loop the manifest and call `this.load.audio(key, url)`
   (the game currently uses **zero** `load.audio` — this is the first).
4. **`AudioBus`:** the constructor takes an optional `musicKey`
   (`new AudioBus(scene, musicKey)`, default `"music"`). `init` resolves the bed:
   if `musicKey !== "music"` and `cache.audio.exists(musicKey)`, the **loaded**
   track is the bed; otherwise it **falls back to the synth `"music"` bed**. It
   synthesizes SFX + `creep-growl` always, and the synth `"music"` bed only when no
   loaded track is used. `addSound` registers the resolved `bedKey` with
   `{ loop: true, volume: MUSIC_VOLUME }`. All `unlock` / `startBeds` / mute / volume
   / spatial-growl logic is untouched. Existing callers (`new AudioBus(scene)`)
   keep byte-identical behavior (bed = synth `"music"`).
5. **Scenes** — the two real `AudioBus` call sites on `main` (`StageScene.js`,
   `DrivingScene.js`) pass the stage's slug: `new AudioBus(this, this.stage?.music)`.

## Track content (toplines shipped in #133)
Each genre renders its **built-in drum + 808 + bass pattern** at a per-stage tempo,
now overlaid with a **per-genre melody topline** (#133): `GAME_TRACK_SPECS` carries
a `melody`/`melodyStepPitches` topline for each of the six stages, and
`buildGameTrackSequencer` overlays it onto the built-in `BEAT_STYLES` pattern
without mutating the preset. The melodic stages — afrobeats (`airport`, 7 active
steps), rnb (`badge`, 6), amapiano (`afterparty`, 6), and bounce (`vendor`, 8) —
carry flowing lines; the beat-forward genres trap (`connector`, 3) and crunk
(`mainStage`, 4) stay comparatively sparse, matching how those genres read as beds.
Every track still ships as an editable `.beatlab.json`, so toplines can be
further tuned **in the Beat Lab editor, where they can be auditioned** (far more
reliable than authoring blind in the spec table).

Timbre note: the bass/instrument voices sound their best when the VCSL samples are
extracted **on the machine running the script** (`scripts/extract-vcsl-*.sh` /
`npm run generate:kit`); without them those lanes use the synth fallback. Drums +
808 render identically either way. This affects timbre only.

## Error handling
- Script: if `loadKitFromDisk()` throws (missing/wrong-rate samples), fail loudly
  with the offending path. If the Rush audio dir doesn't exist, still write the
  `.beatlab.json` and warn that the WAV was skipped (don't crash).
- Rush: `AudioBus` falls back to the synth loop if a track key is missing or fails
  to decode, so the game is never left silent. Global mute/volume unchanged.

## Testing (acceptance)
- **Beat Lab (vitest):** the spec table covers all 6 stages (slugs match the game's
  `scene` values); each spec renders a non-empty `Uint8Array` with a valid WAV/RIFF
  header at 22050 Hz; each produces an export that round-trips through
  `importProjectJson` (`ok: true`).
- **Rush (vitest):** every `STAGES` entry and `DRIVING3D_STAGE` exposes a `music`
  slug present in the audio manifest; `AudioBus` with an unknown/missing `musicKey`
  falls back to the synth bed and never throws; `new AudioBus(scene)` (no key) keeps
  its existing snapshot; mute/volume behavior unchanged.
- `npm run check` passes in both repos.
  - *Note:* Beat Lab's `npm run check` is currently red on a **pre-existing** VCSL
    disk test (sampled WAVs are gitignored/generated). This work must not add new
    failures; the pre-existing gap is tracked separately and is out of scope here.

## Acceptance criteria (from #126)
- Each of the 6 stages plays its own genre-appropriate seamless loop (3D Connector
  reuses the Connector track).
- Each track ships with an editable `.beatlab.json` reopenable in Beat Lab.
- Game mute/volume unchanged; `npm run check` / tests pass in both repos (modulo
  the pre-existing VCSL disk-test gap noted above).
